# 운영 배포와 판매 전 확인 범위

## 구현되어 있는 경계

- 프로덕션/테스트 Compose 독립, 운영에 테스트 부하·가짜 서버 없음
- 운영 계정 설정 누락 시 접근 차단, API에서도 인증 재검증
- exporter 토큰은 서버 환경에만 존재, arbitrary URL/PromQL 입력 거부
- 외부 HTTP redirect를 따르지 않고, 시간·응답 크기·조회 동시성 제한
- 루프백 바인딩, non-root dashboard, read-only filesystem, 자원 제한
- SSH 후보는 로컬 파일에만 저장, 키·명령 실행 없이 설정 정보만 파싱
- 실제 데이터 없는 상태, 지연, 오류 분리; 과거 값을 정상 최신값으로 표시하지 않음
- 스냅샷 기반 조사 내보내기; Prometheus TSDB 및 Alertmanager volume 보존

## 실제 운영 환경에서 검증해야 하는 사항

- 승인된 실제 주소, exporter metric 이름/라벨과 각 지표 계약 일치
- HTTPS 종단·역방향 프록시, 방화벽·VPN, DB 최소권한·TLS
- 실제 부하에서 히스토그램 버킷·표본수·임계값·SLO 조정
- 조직 IdP/SSO, 사용자별 RBAC와 고객/테넌트 데이터 격리
- 일회성 JSON 대신 변경 불가능한 중앙 감사 저장소 및 장기 사고 관리
- 경보 라우팅·당직·메일/메신저 통지는 실제 승인된 수신처가 필요함
- 장애·복구 SLO, 백업/복원, 롤링 배포, HA, 취약점/라이선스 검사
- 예상 서버 수에 맞춘 Prometheus cardinality, retention, federation 또는 장기 저장소

현재는 단일 워크스페이스의 작동하는 제품 기반이며, 다중 고객 SaaS 운영 인증을 완료했다는 의미가 아닙니다. 신규 서버·DB 주소만으로 응용 프로그램의 P99·GC·쿠키 만료가 자동 계측되지는 않습니다. 각 exporter와 애플리케이션 계측을 설치하고 허용된 수집 경로를 구성해야 합니다.

## 실행 비용

기본 테스트는 API 3대와 DB·캐시·프런트·수집/시각화 구성요소를 포함하며 설정상 메모리 상한 합계는 약 2.5GB입니다. 테스트 부하 발생기는 최대 4개 동시 요청으로 제한합니다. 데이터베이스 변경은 테스트 DB 내부 SELECT/캐시 읽기·쓰기뿐입니다. 기존 프로젝트 서버/DB 및 발견된 SSH 호스트에는 접속하지 않습니다.

대시보드는 기본 30초마다 97개 정해진 쿼리를 최대 6개 동시 실행합니다. 조회별 최대 121개 시간 표본, 최대 8개 시계열을 반환합니다. 동일 조회는 20초 캐시하고 동시 snapshot은 3개로 제한합니다. 다수 사용자 운영에는 recording rules, 서버 측 공용 캐시와 서비스별 수집 정책을 추가해야 합니다. 현재 단일 프로세스 캐시는 분산 레이트리밋을 대신하지 않습니다.
