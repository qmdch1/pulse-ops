# 기능·근거 대응표

참고 글의 분석 주제를 아래 제품 기능과 연결했습니다. 이 문서는 내용을 복제하는 요약이 아니라 구현 및 계측 검증표입니다.

| 범위 | 대시보드 구현 | 필요한 실제 근거 |
|---|---|---|
| 트래픽·지연·오류·포화 | 핵심 4지표와 상세 그래프 | 요청 카운터, 시간 히스토그램, 처리 용량 |
| 유입 급감·급증·주기성 | 요청량·지난주 비교, 변화 이벤트 | 7일 전 표본. 주기적 배치는 변경·작업 이력으로 검증 |
| 평균에 숨겨진 지연 | 평균, P50/95/97/99/99.9, API별 P99 | 누적 버킷을 합산한 뒤 백분위 계산 |
| 4xx·5xx·빠른 실패 | 오류율, 성공/실패 지연 분리, 복합 이벤트 | 정규화된 상태코드 라벨, 분모 요청수 |
| CPU·I/O·스로틀 | 프로세스/호스트 CPU, I/O 대기, 제한 주기 | Node exporter, cAdvisor 또는 동등 계측 |
| 메모리 누수·급상승·GC | RSS, GC 후 바닥, GC 빈도/정지, 추세 규칙 | 실측 GC 표본. RSS만으로 힙 누수를 확정하지 않음 |
| 스레드·풀·Little 법칙 | 활성/대기/최대치, 획득 시간, 동시 요청 추정 | 런타임별 풀 계측 |
| 이벤트 루프·프로세스 편차 | P99/최대 지연, 프로세스별 CPU | Node.js exporter. Python 테스트는 미관측 |
| 병목·전체/특정 API | API별 P99, 풀/쿼리 교차 근거 | route 계측, 동일 관측 범위 |
| 연쇄 이탈·재시도 | 수집 이탈/포화, 재시도/오류 복합 규칙 | 실제 LB 헬스체크는 운영 연계 시 추가 |
| 큐·배압 | 깊이, 최장 대기, Kafka lag, 429, 추세 규칙 | 사용하는 큐의 exporter |
| 캐시·TTL·DB 영향 | 적중률, 축출, 만료, DB 쿼리량/지연 | Redis 및 애플리케이션 계측 |
| 계층별 타임아웃 | Gateway/DB 예산, 504, 예산 역전 | 실제 설정값을 exporter가 제공 |
| 느린 성능 저하 | 1주·4주 P99, 동일 시간 요청량 비교 | 7일/28일 이력 |
| 배포·워밍업·카나리 | 버전별 지연, 배포 경과, 10분 지속 악화, Grafana 배포 마커 | 배포 시각·버전 라벨. 자동 롤백 없음 |
| 초기 대응·사후 분석 | 범위 선택, 근거·확인 순서, 스냅샷 내보내기, 경보 이력 | Prometheus 시계열과 Alertmanager 지속 경보 |
| 추가: 인증 만료 | 쿠키/토큰/인증서 잔여 시간과 절대 만료 시각 | 서버 측 만료 메타데이터만 사용 |
| 추가: OS·DB·전송 | 디스크/inode/FD/swap/IOPS, DB 복제/잠금, 드롭/재전송 | 각 exporter |
| 추가: 운영 신뢰성 | 수집 신선도, 오류 예산 2창, 시계 동기화, 재시작/OOM | 승인된 서비스 SLO와 런타임 계측 |

총 지표는 `control-plane/web/data/metrics.json`, 이벤트의 실제 조건은 `control-plane/web/lib/rules.js`, 브라우저가 닫혀 있어도 평가되는 지속 경보는 `monitoring/prometheus/rules.yml`에서 확인합니다. UI 복합 진단과 Prometheus 경보는 서로 다른 역할입니다. UI만의 복합 진단은 별도 통지 서비스를 실행하지 않습니다.

`미관측`은 정상 판정에서 제외됩니다. 새 테스트 스택에 장기 이력을 생성해 넣지 않습니다. 정책 임계값은 관측 대상·노이즈·요청량을 확인하고 운영 적용 전에 조정합니다. 다수 인스턴스의 상관관계는 원인 후보이며 인과 증명이 아닙니다.
